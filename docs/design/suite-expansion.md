## 5. Global constraints checklist (binding for the implementer)

1. Deterministic evaluators only — every case above is contains/not_contains/regex/exact/json_schema/tool_call; no judge.
2. **Regex values may template ONLY numeric vars** (int vars or exprs yielding integers). String-answer parameterized cases use `exact` or `contains` (both template-safe for arbitrary strings). The `{{{n}}}` quantifier spelling is allowed (numeric).
3. Every `pick`/idx combination must yield exactly one correct answer — author verifies exhaustively (pick lists are small by design; ~6 rows each). The idx-table pattern (parallel `expr` array lookups keyed by one `pick`ed index, per `gotcha-decimal-compare` builtin-suite.ts:1181) is the standard for paired data.
4. `expr` bodies are plain JS expressions (array literals, ternaries, string methods, `Math`, helpers `count/counti/len/...`) — no statements, no IIFEs needed anywhere in this plan; no `case-generate.ts` changes.
5. Prompts follow the house style: single task, then "Reply with ONLY … No prose, no commentary."
6. New ids must not collide with the 100 existing ids (verified against the current list; `-param`/`-variants` suffixes used where a fixed sibling exists).
7. Suite metadata: `version: '1.0.0'`; extend `description` with the new areas (multilingual breadth, parameterized retrieval needles, stats, expanded code/logic, 7 new vision fixtures; Phase B adds multi-turn + tool-loop mention).
8. Backward compat untouched: no `InlineCase` field changes in Phase A, so localStorage custom cases, YAML round-trip, and IDB v1 records are unaffected.


## RISKS
- Suite doubles to 200 cases → per-model run time roughly doubles (sequential runner); long-context cases add token cost. No mitigation in this workstream; a tag-filter run option is a separate feature.
- Ambiguity escapes in pick-list combinatorics (e.g. a language-ID snippet identifiable as two languages, a Winograd item a model reads differently): every idx-table row must be hand-verified; recommend a one-time exhaustive materialization pass (loop all idx values) before merging.
- Exact-match translation cases can under-credit valid synonyms (e.g. 'Haus' vs 'das Haus'); mitigated by choosing words with a single canonical no-article translation and forgiveFormatting for case, but a residual false-fail rate remains — watch first runs and add acceptWithRemark clauses where needed.
- The `{{{n}}}` regex-quantifier templating trick depends on fillTemplate's exact replace regex (case-generate.ts:76); a future template-syntax change would silently break those two format cases — add a code comment at each use site.
- evaluator-direct.ts does NOT validate minItems/maxItems (only type/required/properties/enum/items), so 'exactly 2 strings' in json-string-array-two is under-enforced (same latent gap as existing json-array-of-three); acceptable for consistency but worth a follow-up evaluator patch.
- 16 of the 100 new cases (multi-turn + tool-loop) are blocked on the separate case-type workstream; if that slips, the suite lands at 184 and tool-use/multi-turn tag targets are missed.
- New 5x7-bitmap-font OCR fixtures may be systematically harder than the current anti-aliased OCR fixture for small VLMs, shifting vision scores down across the board; verify against 2-3 known-good vision models (qwen2.5vl, gemma3) before finalizing glyph scale.
- Regenerating vision-fixtures.ts from the new script re-draws the existing 3 fixtures; if the re-drawn bytes differ, historical runs remain comparable only because expected answers are unchanged — still, diff the rendered images visually before committing.
